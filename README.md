# Unicorn

Unicorn is a smart AI companion for Android. It is two things in one install:

- **Writing tools above the keys in every app.** Fix grammar, change tone, translate, and Ask Unicorn: a prompt bar
  the keys type into, with slash commands (`/reply` to a copied message, `/email`, `/improve`, `/shorter` ...) whose
  answer goes into the app with one tap. Plus voice typing, a select-all/clear/undo key, the user's own words and
  text shortcuts, and suggestions of earlier questions while typing in AI apps.
- **A lifestyle app for your AI life.** Today shows your Curiosity rings, then there are Insights, a Library of AI
  conversations, Near you trends, and You for privacy controls.

## Meta's model inside Unicorn

Built for the Meta Global AI Developer Hackathon (2026). Every AI writing tool in Unicorn runs on **Meta's Muse
model (`muse-wonder-1.0`) through the Meta Model API**: Tone, Grammar, Translate (23 languages), and Ask Unicorn
with `/reply`, `/email`, `/improve` and more, in every app on the phone.

- `backend/src/ai.ts` `runTaskMeta` calls Meta's messages endpoint (`https://api.meta.ai/v1/messages`) with the
  same task prompts the app has always used, and reads back `{"results": [...]}`.
- `backend/src/index.ts` `runAi` sends each request to Meta first. If Meta times out (12 s), fails or drops part of
  the user's text, Claude Haiku answers instead, so the tools never go dark. A refusal is final.
- `backend/wrangler.jsonc`: `AI_PROVIDER: "meta"`, `META_MODEL`, `META_API_BASE`. The key is a Worker secret
  (`wrangler secret put META_API_KEY`). The phone never holds an AI key, and text is never stored or logged.
  Only which model answered is logged.
- `GET /v1/health` reports `"provider": "meta"` on the live backend.

Launch video: `video/` (Remotion), filmed from scripted emulator takes (`tools/demo/`, `glidetest/`).

```
unicorn/
  app/            Android app: AOSP LatinIME engine (Java + C++), Unicorn code (Kotlin, ai.unicorn.*)
  backend/        Cloudflare Worker: AI proxy (Meta Muse via the Meta Model API, Claude Haiku as fallback), rate limits, consented aggregated trends
  branding/       Logo source, Play Store icon
  tools/          Generators: icons, key theme, Android.mk, engine hooks, Model2Vec converter
  glidetest/      Emulator test app: glide gate, plus the demo video's chat screen and shot runner
  video/          Remotion project for the launch video (see video/README.md)
```

## Architecture

| Layer | Where | Notes |
|---|---|---|
| Typing engine | `app/src/main/java/com/android/inputmethod/**`, `app/src/main/jni` | AOSP LatinIME (Apache-2.0), native dictionary engine built with ndk-build |
| Glide typing | `ai/unicorn/glide/*`, the batch path in `Suggest.java` | Unicorn's own decoder: SHARK2-style shape and location matching of the swipe against each candidate word's path over the real key centers, with an elastic alignment, weighed with the dictionary's word frequency, a next-word table (`assets/glide/en_next.bin`, built by `tools/make_glide_bigrams.py` from Tatoeba, CC BY 2.0 FR), what the user typed before, and the user's own words. AOSP's native gesture decoder is an empty stub, so batch input never reaches it. On in You > Writing. Gate: `tools/glide-stress.sh`, report in `docs/research/glide-typing-report.md` |
| Look | `tools/keyboard_themes.json` → `res/drawable/unicorn_t_*`, `values/themes-unicorn-generated.xml`, `keyboard/KeyboardPalettes.kt` | Nine themes, generated by `tools/make_keyboard_themes.py` (the Unicorn pair by `tools/make_unicorn_theme.py`). Default is Classic, following the system light/dark mode; You > Look picks another |
| Hooks into the engine | `LatinIME.java`, `InputLogic.java` (search `ai.unicorn.Unicorn`) | Inserted by `tools/patch_engine_hooks.py` |
| Prompt saving | `ai/unicorn/memory/PromptCapture.kt`, `CaptureSource.kt` | Hard-coded allow-list of five AI makers only: ChatGPT, Claude, Perplexity, Grok and Google (Search & AI Mode, Gemini). See the privacy model below |
| Key layout and feedback | `res/xml/rows_qwerty.xml`, `row_qwerty4.xml`, `layout/suggestions_strip.xml`, `keyboard/KeyFeedback.kt`, `app/KeyFeedbackPicker.kt` | Samsung-style: a number row, `?123 , space . return`, and emoji at the left of the suggestions next to select all. Key presses give a short vibration by default (our own effect, as the system tap is off on many phones), or a click sound, both or nothing, chosen in You |
| Size and position | `keyboard/KeyAreaSize.kt` (math), `KeyArea.kt`, `KeyAreaEditor.kt`, `TapAim.kt`, `app/SizeScreen.kt`; hooks in `KeyboardSwitcher.loadKeyboard`, `InputView`, `KeyDetector`, `LatinIME.onComputeInsets` | QWERTY never changes; only the whole area does. Resize handles (⋯ in the toolbar, or You > Look > Size and position): height, width, slide sideways, lift off the bottom, Reset. Each orientation keeps its own size. One-handed docks left or right, with switch-side and full-width buttons in the empty side. Limits: letter keys at least 29 dp wide, and the whole input view (toolbar, suggestions, keys, lift, navigation bar) within 85% of the screen height; the engine's default size is always allowed. Edge taps: a tap within ¾ key beside narrowed keys goes to the row's outer key, and the lifted space ignores touches. Learn my aim (on by default, phone only): after 40 clean taps on a letter, its touch area moves up to ¼ key toward where this person lands, only between touching letters. Glide reads real key positions and is unaffected. `tools/size-check.sh` drives all of it on the emulator |
| Memory and recall | `ai/unicorn/memory/*` | Room DB, Model2Vec static embeddings (int8), sign-bit and int8 vector index, LRU cache |
| Keyboard toolbar and AI panel | `ai/unicorn/keyboard/*` | Plain Views, no Compose in the keyboard process |
| Ask Unicorn prompt bar | `keyboard/AskSession.kt`, `AskUnicorn.kt`, `PromptChips.kt`, `UnicornBar.kt` | While open, `LatinIME.onEvent` routes keys to the prompt (`Unicorn.interceptKey`). The app kind (email, chat, social) comes from the package and input type; a copied message is read only when the user asks for a reply or summary |
| Reply context | `keyboard/RecentMessages.kt` | With the user's permission (notification access), the last messages of recent chat and email conversations, kept in memory for six hours. `/reply` answers the latest conversation in the app being typed in; copied text is used only if copied in the last 15 minutes. Android 15+ redacts some notifications (one-time codes, and on some builds all SMS) for third-party listeners; those are skipped |
| Voice typing | `keyboard/VoiceTyping.kt` | Android `SpeechRecognizer` (on-device service as fallback), started by the mic in the suggestions. The engine's switch to a separate voice keyboard no longer works on current Android |
| Your words and shortcuts | `ai/unicorn/words/*`, `app/WordsScreen.kt` | Room DB of single words learned in `InputLogic` in every non-private field, also where the app turned autocorrect off; undoing an autocorrection learns the word at once (never password or incognito fields). New words and names used twice, and words added by hand, feed `UserBinaryDictionary`; shortcuts lead the suggestions via `Shortcuts.apply` and replace the word on space |
| App | `ai/unicorn/app/*`, `ai/unicorn/ui/*` | Jetpack Compose |
| Trends | `ai/unicorn/trends/TrendsRepository.kt`, `backend/src/index.ts` | Anonymous signals in, aggregates out, with a minimum number of people. Give-to-get: only people who share see them. Non-sharers get the blurred peek with the area's progress to 25 people |
| Hunches | `backend/src/hunches/*`, `trends/Hunches.kt`, `trends/Places.kt` | Playful, labelled guesses about what the area is asking, until real trends exist. Several hundred templates filled from NWS alerts, MET Norway forecasts, a holiday calendar, the time of day, state store chains, metro teams and airports, and a per-town fact sheet that Claude Haiku writes once a fortnight (cached in KV). Dangerous weather gets a plain safety line and no jokes |
| Consent nudges | `app/Nudges.kt`, `app/UnicornCard.kt` | The blurred Near-you peek, "See exactly what's shared" (this week's prompts run through the same signal code), and stardust: 10 a sharing day grows the Unicorn card (sparkles, wings, aurora, golden frame) |
| App lock | `app/AppLock.kt`, `app/MainActivity.kt` | Fingerprint, face or the phone's screen lock to open the app, re-locking after a chosen time; blank in recents on Android 13+. The keys show no saved prompts or chat names over the lock screen |
| Website | `website/` | Static landing page, blog and privacy page with live hunches and an early-access form (`POST /v1/waitlist`). Live at https://unicorn-site.m-vamshikrishna22.workers.dev |
| First-run reveal | `app/Reveal.kt` | Shown once after setup: the Unicorn hatches, a one-of-a-kind shareable Unicorn card (from the install id), a live AI rewrite demo, and what's happening nearby |

**How a send is detected.** In priority order:

1. The keyboard's action key (send, search, go).
2. The app clears the field: either a selection update to empty, or a restart of the same field with empty text.
3. The field disconnects and reconnects empty within 2 seconds. This covers apps that hide the keyboard on send.

Text the user deletes, and text left in a field that closes, is never saved. Every decision is written to an on-device
log without any prompt text. See You > Saving activity log.

**Measured.** On a desktop JVM with 50k prompts:

| Metric | Value |
|---|---|
| Encode a prompt | 2.8 µs |
| Search | 188 µs |
| Recall@5 vs exact search | 0.97 |

On an Android 15 emulator, debug build, 5k prompts:

| Metric | Value |
|---|---|
| Full recall, typical | 209 µs |
| Full recall, slowest 5% | 386 µs |

Insights > Suggestion speed measures recall speed on a real phone.

## Build

Requirements: JDK 17+, Android SDK with platform 36, NDK 26.1.10909125. `local.properties` points at the SDK.

```bash
./gradlew :app:assembleDebug
./gradlew :app:testDebugUnitTest
./gradlew :app:assembleRelease :app:bundleRelease
```

The debug build can target a local backend with `-PunicornApiUrl=http://10.0.2.2:8787`. Cleartext HTTP is allowed
only to the emulator host, and only in debug builds.

The release build is signed with the debug key for testing. Create an upload key before publishing.

## Backend (Cloudflare Worker)

Deployed at `https://unicorn-api.m-vamshikrishna22.workers.dev` with the D1 database `unicorn-db`.

```bash
cd backend
npm install
npm run dev                       # local, mock AI, debug region header allowed
npx wrangler secret put ANTHROPIC_API_KEY   # turns on the AI tools in production
npm run deploy
```

| Endpoint | Purpose |
|---|---|
| `POST /v1/ai` | Runs `grammar`, `tone`, `translate`, `compose` and `write` (Ask Unicorn: command, instruction, draft, copied thread, app kind) on Claude Haiku 5.5 with structured output. Limits are 150 requests per install per day and 50,000 for everyone per day, a cost ceiling of about $5/day. Text is never stored or logged |
| `POST /v1/signals` | Takes consented anonymous signals (topic, brand, intent, normalized question). The area is Cloudflare's state-level IP geolocation. Contributors are counted with a per-day salted hash, so they can't be linked across days |
| `GET /v1/trends` | Returns items shared by at least `TRENDS_MIN_PEOPLE` (25) different people, plus `sharersToday` for the area's progress |
| `GET /v1/hunches` | Ten hunches for the town (from the phone when the user turned on their neighborhood, otherwise the IP's city), with the reason for each and weather credits. A new town's fact sheet is one Haiku request, capped at 3 per install and `DAILY_PACK_LIMIT` per day |
| `POST /v1/waitlist` | Early-access email and phone type from the website (`SITE_ORIGINS`), rate-limited by a daily hashed IP |

A cron job purges signals older than 30 days.

## Privacy model

- **Saving prompts is off until the user turns it on.** Only the apps in `CaptureSource` are eligible.
- **Fields that are never saved:** passwords, numbers, email and phone fields, and fields an app marks as private.
- **Memory stays on the phone.** It is app-private, credential-encrypted storage, and `allowBackup="false"`.
- **Private fields are left alone** (`keyboard/SensitiveField.kt`): passwords, PINs, one-time codes, number, phone
  and email-address fields, fields hinted as OTP/CVV/UPI/card number, incognito fields, and banking and payment apps
  get no AI bar, no voice, no word learning, no prompt saving and no undo copy. Covered by `SensitiveFieldTest`.
- **Unicorn's code can't break typing:** every engine hook runs inside `Unicorn.safely`, which logs the error type
  (never text) to the saving activity log and carries on with plain keys.
- **Learned words are single words only,** kept on the phone, never from password or incognito fields, and can be
  removed one by one or all at once in You > Your words.
- **Copied text is read only on request** (Reply to copied, Summarize copied), and only then sent to the AI.
- **Neighborhood hunches are opt-in.** The area's name and coordinates rounded to about a mile are sent to pick
  hunches and aren't kept with anything identifying.
- **Trends sharing is a separate opt-in,** and "See exactly what's shared" shows the user's own week first. It sends
  topics, brands, intents and short questions only. Questions must read as questions (chat lines are dropped), and
  topics and questions containing the user's learned names or new words, digits, emails or links never leave the phone.
- **App lock** uses the phone's own biometrics or screen lock, so Unicorn stores no PIN.
- **The business model is aggregated insights,** not raw prompts. Google Play's User Data policy forbids selling
  personal and sensitive user data.

## Autocorrect checks

`tools/autocorrect_check.sh` types contractions, common typos and correct words through the on-screen keys of the
emulator (harness app installed) and checks the result, including backspace undoing a correction. Run it before
every release: `ADB=/path/to/adb SERIAL=emulator-5556 tools/autocorrect_check.sh`.

## Glide typing checks

`tools/glide-stress.sh` runs the whole glide typing gate with no one at the phone: the JVM harness (synthetic swipes
of the dictionary's 1,000 and 10,000 most common words on three screens, plus sentences), the emulator end-to-end test
(the `glidetest/` app injects swipes as real touches through the keys: words, sentences, rapid and fast swipes, taps,
capitals, backspace, alternatives, cancelling, other start keys and rotation), and a 22-minute soak watched for crashes,
ANRs and memory. It writes `docs/research/glide-typing-report.md` and fails under the bar. Run it before every release:
`ADB=/path/to/adb SERIAL=emulator-5556 tools/glide-stress.sh`. Weights are tuned on other words with
`GLIDE_TUNE=1 ./gradlew :app:testDebugUnitTest --tests ai.unicorn.glide.GlideTuning`.

## Free AI limits

Each install gets `DAILY_AI_LIMIT` (150) AI requests a day, and `FAIR_SHARE_AI_LIMIT` (40) once the day's global use
passes 80% of `DAILY_GLOBAL_AI_LIMIT`. Nothing is shown to the user: when the limit is reached the AI tools quietly
hide until the reset (`UnicornPrefs.aiPausedUntil`) and typing goes on. The Worker logs `ai global usage` at 80% and
100% of the global budget, for an alert. Rewrites that drop more than 40% of a long text are rejected
(`keepWhole` in `backend/src/ai.ts`).

## Testing prompt saving locally

The emulator has no AI apps, so `harness/` installs a small chat screen under `com.openai.chatgpt` that covers three
cases: a Send button, Send with the keyboard hidden first, and the keyboard action key. Install it only on an
emulator.

## Known limitations

- Glide typing is English only. Words whose keys lie on one straight line share a path ("for" and "four", "to" and
  "too"); the previous word usually picks the right one, otherwise it is in the suggestions. It is measured on
  synthetic swipes and injected touches on the emulator, not yet with a real hand on a real phone.
- Only the English dictionary ships. More languages should be downloadable later.
- Replies can't read the chat on screen (that would need an accessibility service). They use message notifications
  (if allowed) or text copied in the last 15 minutes. Sideloaded installs must first allow restricted settings in
  App info before Android lets them turn on notification access.
- Suggestions now also show in fields that ask for none (autocorrect stays off there), like SwiftKey; passwords,
  emails and web addresses still get none.
- Google Trends and Google News were removed in 0.4.0. Hunches use MET Norway (CC BY 4.0, credited in the app) and
  US National Weather Service alerts (public domain). Town fact sheets are written by an AI and can be wrong about
  small towns; hunches are always labelled as guesses.
- The app lock's fingerprint prompt is untested on the emulator (it has no screen lock); the "set up a screen lock
  first" path is tested.
- Voice typing is tested up to listening and error handling on the emulator; real speech is untested.
- Landscape (fixed in 0.5.1) is checked on an Android 15 emulator with the navigation bar at the side and a camera
  cutout: the keys take the window's width between them, not the screen's (`ResourceUtils.getDefaultKeyboardWidth`),
  and stay above the back and switch buttons Android draws under the keys (`InputView`). Real phones in landscape,
  and tablets, are untested.
- Real AI apps (ChatGPT, Gemini, Claude, Perplexity) are untested on a physical phone. Check
  You > Saving activity log after trying each one.
